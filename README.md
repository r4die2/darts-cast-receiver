# Табло CalcURate

Откройте `preview.html` в браузере для просмотра примера игры без Chromecast.
Файлы `index.html`, `style.css` и `receiver.js` должны находиться рядом с ним.
Пример включается только параметром `?preview`; при обычном запуске отображается реальная игра.

Для проверки изменений в консоли браузера: `CalcURatePreview.throw(60)` — уменьшить остаток,
`CalcURatePreview.nextPlayer()` — сменить игрока, `CalcURatePreview.reset()` — вернуть пример.
`leg-win-preview.html` открывает отдельный экран победы в леге; в основном превью его
также можно показать через `CalcURatePreview.finishLeg(0)`.
`bot-leg-preview.html` показывает тот же экран победы с подходами бота и информацией
о турнире из записи базы.
Для публикации замените соответствующие файлы GitHub Pages этой версией.
Показ последнего подхода требует обновлённого приложения, которое отправляет `lastVisit`.
Последний корректный снимок табло сохраняется в хранилище Web Receiver и
показывается после перезапуска приёмника до получения нового сообщения. При
восстановлении виден статус «ПЕРЕПОДКЛЮЧЕНИЕ…»; актуальный счёт по-прежнему
передаёт телефон. Хранилище может быть очищено телевизором или платформой.

При потере последнего отправителя или сети приёмник оставляет табло на экране,
а в левом нижнем углу показывает «ПЕРЕПОДКЛЮЧЕНИЕ…». Статус исчезает только
после получения полного корректного снимка; подключение телефона, неверное
сообщение или часть большого снимка его не скрывают. Это работает в X01,
с ботом, крикете и турнирах. Простой без бросков не считается обрывом.
Для этого немедийного приложения отключён idle timeout CAF; стандартный
тайм-аут проверки связи с отправителем сохранён. Обычная остановка трансляции
пользователем по-прежнему обрабатывается платформой Cast.

Для применения опубликуйте `index.html`, `style.css` и `receiver.js`
из этой папки по прежнему адресу GitHub Pages, сохранив остальные файлы.
App ID и namespace менять не нужно; обновление APK для этой правки не требуется.
Уже запущенный приёмник нужно один раз закрыть и снова открыть после публикации.
При перезагрузке Chromecast или принудительном закрытии страницы системой
непрерывное изображение не гарантируется.

Проверки: `node tools/cast/test-published-receiver.mjs`,
`node tools/cast/test-cricket-receiver.mjs` и
`node tools/cast/test-tournament-receiver.mjs`.
Браузерные тесты имитируют события SDK и сети, но не заменяют проверку
кратковременного обрыва Wi-Fi на физическом Chromecast.
